# Permission matrix

This describes application roles, not a malicious DB/host administrator. Finance implies operations; operations implies reviewer, CRM all-leads and project user. The generated pilot admin additionally has native system administration. An ordinary internal account's native CRM/project/contact grants remain in effect; adding new staff requires reviewing those native groups. The original specification's owner/admin terminology is therefore broader than the finance role alone.

Legend: R read, C create, U update, A approve/action, D download, E export. Every grant also requires native ACL/rules and active company scope. E additionally requires Odoo's native export permission; grants are not created by this change.

| Information / model | Finance owner | Operations | Ordinary internal | Contractor | Guest |
|---|---|---|---|---|---|
| CRM customer/job personal details | R/C/U/E, governed stages | R/C/U/E, governed stages | Native CRM read if granted; field-service changes denied | Explicit assigned portal projection only | None |
| Contacts `res.partner` | Native R/C/U/E; private rates | Native R/C/U/E, no private rates | Existing contact ACL; no private rates | Existing own portal contact scope; no field-work CRM | Native public company identity only |
| Tasks/report/photos | R/C/U/A/D/E per native project and process | R/C/U/A/D/E per native project and process | Native project scope; reviewer action only if reviewer role | Current assigned, active job projection and images; draft/correction report upload/submit only | None |
| Extra `field.work.photo` | Parent task scope and review lock | Parent task scope and review lock | Parent task rights, locks, size/count/type limits | No model RPC; scoped portal upload/download | None |
| Material cost, pricing snapshots, margins | R/U/E as allowed; snapshots generated by dispatch | Denied, including read/search/group/export | Denied | Denied | Denied |
| Customer receipts `field.work.payment` | R/C/A-cancel/E within company/lead rules | R/C/A-cancel/E, customer kind only | Denied | Denied | Denied |
| Contractor payouts `field.work.payment` | R/C/A-cancel/E | Denied | Denied | Denied | Denied |
| Payment/cancel dialogs | Own creator, allowed company, appropriate kind | Own customer-kind dialogs only | Denied | Denied | Denied |
| Correction dialog | Own creator, allowed task/company, reviewer | Same | Only reviewer and accessible task | Denied | Denied |
| Entitlement events | R/E only; creation/reversal through private governed actions | May cause private event through authorized closure/correction; cannot read it | Denied | Denied | Denied |
| Statement/snapshot/HTML/PDF | Own creator + active company + finance; R/C/regenerate/D/E | Denied | Denied | Denied | Denied |
| Native attachments/files | Bound resource ACL; public/token files are separate native capabilities | Same bound resource scope | Native rules | Field-work task/project deny rules also protect generic binary paths | No private fixture file access; intentionally public assets remain public |
| Secrets/backups/system settings | Native system administrator/operator only, not implied by finance | Denied | Denied | Denied | Denied |

No payment/event editing, copying or deletion is granted. Correction appends or cancels through recorded actions; reporting never creates a payment or Morning document. Contractor reassignment revokes old scoped access on the next request. Previously downloaded bytes cannot be revoked. Existing shared/project/contact rules must be reviewed if the business intends to add an additional restricted internal field-manager role; the current restricted mobile role is the contractor portal.
