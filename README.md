# Odoo Pilot - ניסוי בענן

Odoo Community 18, PostgreSQL 16 ומודול דיווח תמונות לפני ואחרי.
המערכת מיועדת לפיתוח ולניסוי ב־GitHub Codespaces, בלי התקנת Odoo במחשב.

## הפעלה מהדפדפן

1. במאגר לוחצים **Code → Codespaces → Create codespace on main**.
2. ממתינים לבניית סביבת העבודה ולהתקנה הראשונית. ההתקנה נמשכת כמה דקות.
3. בטרמינל של Codespaces מריצים:

   ```bash
   python3 scripts/pilot.py status
   ```

4. כאשר מוצג `Odoo is ready`, מעתיקים את שם המשתמש והסיסמה שנוצרו.
5. בכרטיסיית **Ports** פותחים את פורט **8069** באמצעות סמל הדפדפן.
   משאירים את נראות הפורט **Private**. הכניסה לכתובת מוגנת גם באמצעות חשבון GitHub.
6. נכנסים ל־Odoo עם הפרטים שהוצגו. הממשק מוגדר לעברית ולשעון ישראל.

אם עדיין לא מוכן:

```bash
tail -n 60 .local-data/odoo.log
```

## ניסיון הפיצ׳ר הראשון

1. פותחים את אפליקציית פרויקטים ואת הפרויקט **עבודות שטח - פיילוט**.
2. פותחים את משימת **החלפת ברז במטבח - ניסיון**.
3. בלשונית **דיווח מהשטח** לוחצים על **סיום עבודת שטח** בלי תמונות - צפויה חסימה.
4. מעלים תמונה לפני ביצוע ותמונה אחרי ביצוע, ואז מנסים שוב - המשימה אמורה להסתיים.

הפיצ׳ר דורש תמונה אחת בכל שדה. החסימה חלה גם על שינוי מצב המשימה דרך API או ייבוא.
משימות רגילות אינן מושפעות; אפשר להפעיל בהן את הדרישה בכפתור **הפעלת דיווח שטח**.
אי אפשר לבטל דרישה שהופעלה. לתיקון תמונה אחרי סיום יש לפתוח מחדש את המשימה.
מצב הסיום הרשמי הוא Done (`1_done`); שם של עמודת קנבן אינו קובע את מצב הסיום.

## עצירה, שמירה ועלויות

- עוצרים את ה־Codespace דרך GitHub כשמסיימים לעבוד. עצירתו עוצרת גם את Odoo.
- סביבת העבודה והנתונים נשמרים במהלך חיי אותו Codespace, כולל עצירה וחידוש.
- מחיקת Codespace או מחיקתו האוטומטית עקב חוסר פעילות עלולות למחוק את נתוני הניסוי.
- קוד שנשמר ב־Git נשמר במאגר; תמונות ומסד הנתונים אינם נשמרים בו.
- לחשבון GitHub אישי יש מכסת שימוש חינמית. מחשוב ואחסון נמדדים בנפרד.
  בודקים את המכסה הזמינה ואת מגבלות התקציב בחשבון לפני הפעלה.
  בלי אמצעי תשלום השימוש נחסם כשנגמרת המכסה. עם אמצעי תשלום יש להגדיר תקציב
  שחוסם שימוש נוסף כדי להימנע מחיוב.
- זו סביבת פיתוח ולא אירוח עסקי רציף. אין צורך ב־Cloudpepper במסלול הניסוי הזה.

## סיסמאות ונתוני ניסיון

פרטי כניסה וסיסמת ניהול מסד הנתונים נוצרים אקראית ב־`.local-data`, שמוחרגת מ־Git.
הסיסמה הקבועה בקובץ Compose מיועדת לחיבור הפנימי למסד הניסוי בלבד; פורט מסד הנתונים
אינו מפורסם. אין להפעיל תצורה זו כשרת ייצור או להכניס אליה נתוני לקוחות אמיתיים.
המודול משתמש בהרשאות Project הקיימות; פורטל קבלנים והפרדה בין קבלנים אינם ממומשים עדיין.

## בדיקות

ה־workflow שב־Actions מריץ את 11 בדיקות האינטגרציה על Odoo ו־PostgreSQL אמיתיים.
אפשר להריץ אותן גם מהטרמינל של Codespaces:

```bash
python3 scripts/pilot.py test
```

הבדיקות משתמשות במסד נפרד בשם `odoo_pilot_tests` ואינן משנות את מסד הניסיון.
להרצה נקייה חוזרת אפשר למחוק את מסד הבדיקות בלבד לפני הרצת הבדיקות.
