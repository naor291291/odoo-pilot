# Production handover

The stack requires an always-on Linux host with Docker Compose, an approved DNS name pointing to it, and an approved encrypted off-site Restic repository. An existing company-managed host can be used. Codespaces stays a development environment.

## Initial setup

1. Check out a verified release. In this directory copy `.env.example` to `.env`, `delivery.env.example` to `delivery.env`, and `odoo.conf.example` to `odoo.conf`. Restrict the files to the host administrator and the required container user. Use separate random database credentials and a unique Odoo database-management secret. Keep both delivery channels and inbound off. Pin all three supported images by digest. Use a Caddy release supporting the `request_body` directive.
2. Initialize privately with `docker compose up -d db` and `docker compose run --rm odoo odoo -d field_crm -i field_work_photos --without-demo=all --stop-after-init`. Before starting the proxy, use `docker compose run --rm odoo odoo shell -d field_crm` to set a strong initial administrator password, create named users and assign the owner and operations groups. Enter secrets interactively, with no command-line password. Set `web.base.url` to the final HTTPS origin, `web.base.url.freeze` to `True`, and `report.url` to `http://127.0.0.1:8069`.
3. Start with `docker compose up -d`. Only the proxy publishes ports 80 and 443. Confirm automatic HTTPS, HTTP redirect, blocked database management, login, PDF rendering and role isolation with synthetic work. Check the production mail and WhatsApp account setup in separate test mode before inviting users. For upgrades, take a verified backup, stop Odoo, update the checkout, run Odoo with `-u field_work_photos --stop-after-init`, then start it again.

## Delivery and status rules

The deployment activates automation for exactly one configured database and company. Set `FIELD_WORK_DELIVERY_DB=field_crm` and `FIELD_WORK_DELIVERY_COMPANY` to the verified Odoo company ID. Enable `FIELD_WORK_AUTO_STAGES=1` after testing. A saved quote number and PDF move a complete quote to **הצעה נשלחה** and queue delivery. The invoice number and PDF permit automatic closure once execution is approved and customer collection is complete, regardless of the order in which these conditions are met. The existing manual workflow remains available. A queued quote means delivery was requested; use the attempt log to verify provider acceptance or failure.

- Set `FIELD_WORK_EMAIL_MODE=test`, configure authenticated SMTP over TLS, and set the allowed recipient to a controlled mailbox. The recipient on the synthetic customer record must match. Verify the envelope and PDF at that mailbox. Configure sender-domain authentication with the provider.
- Set `FIELD_WORK_WHATSAPP_MODE=test` and enter the supported Graph API version, business phone ID and token. Set the test recipient to its international digits. Create and obtain approval for one Hebrew template per document type, each with a document header and a body with one positional variable for the document number. Mark consent on the synthetic lead. WhatsApp uses a media ID and does not expose the PDF through a public link.
- Register `https://<CRM domain>/field-work/whatsapp/webhook` in Meta with the verification token, app secret, and the messages subscription. Test rejection of invalid signatures, confirmation of delivery and failure, and signed duplicate events. Turn on `FIELD_WORK_WHATSAPP_INBOUND=1` only if inbound text should create leads. A distinct WhatsApp message ID creates one lead; attachments and other event types are ignored. Verify that test-number callbacks cannot target a different company.
- Recreate the Odoo container after changing the delivery environment. Move each verified channel from `test` to `live` only after the owner authorizes customer use. The scheduled job processes pending attempts once. Use the failed attempt record to retry after fixing the recipient or provider. A result that needs investigation may have reached the recipient, so reconcile it with the provider first.
- The chart page shows six months of posted receipts by payment month, estimated profit by work opening month, and the conversion of each opening-month cohort at its current stages. These are separate measures, with a 50% conversion target.

## Encrypted off-site backup and restore rehearsal

Initialize the approved Restic repository outside Odoo. Set its credentials and password in a protected host environment. Run `./backup.sh` as the service operator from the scheduled backup job. It briefly stops Odoo, captures PostgreSQL and the filestore as a consistent pair, starts Odoo, and transfers both to the encrypted repository. Verify the successful exit code and snapshot ID before relying on the schedule. Set retention with the business owner.

Rehearse using a separate Compose project on an isolated host or network. Use unique volumes and credentials. Leave **all delivery modes, inbound and automatic transitions off** and start no public proxy. Restore a selected Restic snapshot, then restore `database.dump` into the newly initialized, empty `field_crm` database as the Odoo database owner with `pg_restore --no-owner --no-privileges --exit-on-error`. Extract `filestore.tar` into the isolated Odoo data volume with ownership suitable for the Odoo image. Confirm database counts, attachment checksums, a login, an invoice PDF, contractor photo access and a report. Record snapshot ID, duration and results. The repository CI restore drill uses synthetic data and does not verify the production destination or its credentials.

## Physical phone acceptance

On iPhone Safari, sign in with the synthetic contractor and open `/my/field-work`, then use Share → Add to Home Screen. On Android Chrome, use the browser menu → Add to Home screen. Launch from the icon and verify the correct portal URL, sign-in and access to only assigned work. Capture one before and one after photo on each device, save the draft, reopen it, submit it, and check the images from the operations account. Record devices, browser versions, outcomes and any issues before handling real customer data.
